# Release v0.1.0

Date: 2026-10-18
Status: release candidate. The tag is created on `main` only after the maintainer approves the
Phase 4 close-out. The tag command is queued in `notes/reports/p4-closeout.md`.

## Highlights

The first tagged release of the JupyterHub container deployment service. It manages up to fifty
LXD containers on the FRESH lab host, is fully typed and tested, and follows the UBC-FRESH dev
workflow.

## Changes

### P0 Bootstrap and hardening

- Adopted the UBC-FRESH dev workflow: `AGENTS.md`, `ROADMAP.md`, `CHANGE_LOG.md`, `notes/`, the
  validator, the green dashboard, pre-commit, and CI.
- Replaced the ad-hoc container code with a typed service layer: `web_service/config.py`,
  `web_service/lxd_utils.py`, and a hardened `web_service/routes.py`.
- Raised the deployment limit from 30 to 50, on host ports 8101 to 8150, configurable through
  `JHD_MAX_DEPLOY` and `JHD_HOST_PORT_BASE`.

### P1 Capacity and operations

- `GET /health` and `GET /capacity`.
- A pylxd transport error is translated to a JSON 502.
- The operations runbook: routine tasks, monitoring, and the full-capacity incident.

### P2 API and access control

- Shared-token authentication. `JHD_AUTH_TOKEN` protects every route except `/health`, `/login`,
  and `/logout`; API clients use `Authorization: Bearer`.
- The access-model page and ADR 0003.

### P3 Deployment and packaging

- `scripts/install.sh`: an idempotent install and upgrade with `--dry-run` and `--apply`.
- `nginx/nginx.conf`: a reverse proxy that serves the service at the site root.

## Verification

- A clean clone of `main` passes the full dashboard: lint, format, strict types, 235 tests at 99.50
  percent branch coverage, the validator, and the docs build. See `notes/reference/acceptance.md`.

## Known gaps

- One shared token, not per-user accounts; no audit trail of who made a change.
- The service is served at the site root; a path prefix is not supported.
- The acceptance rehearsal ran on the lab host, not on a blank physical machine.
- No container image or PyPI package.
- The nginx config has no TLS block; the operator adds one.
